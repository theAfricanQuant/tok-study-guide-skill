# Learning design for every lesson

Use this reference when designing any guide, whether it is a one-off or part of a continuing course. The teaching methods shape how learners work with the material; they do not replace or expand what the sources support. Keep source-based claims tied to their anchors, and identify explanations, examples, or practice prompts that you created.

## Start from a mission and a finish line

- Ground a continuing course in the learner's practical reason for learning, prior work, constraints and demonstrated level. Use existing mission or learning records when available; ask only when the missing context would materially change what to teach.
- Set one concrete finish line for each guide: what the learner should be able to explain, solve, build, decide, write or perform. Supporting outcomes should lead toward that win.
- Separate knowing an idea from using or performing it when both matter; teach only the knowledge needed for the practical finish line.
- If prior knowledge is uncertain, use a short, low-stakes prompt and give useful feedback. Treat the answer as evidence about the starting point, not as a pass/fail gate. Never assume mastery from familiarity, confidence, silence or finishing the page.
- Fit scope and challenge to the source and the learner. A guide may be substantial when the material needs it, but should not add chapters or activities to meet a quota.

## Build a teach–attempt–feedback loop

Use this cycle for each major idea when it fits the goal:

1. **Explain in chunks:** introduce foundations in a sensible order, define needed terms, and connect each part to the source evidence and the larger argument.
2. **Model:** for a procedure or performance, show a worked example. Make the important choices visible and explain why they work.
3. **Elicit an attempt:** ask the learner to recall, predict, explain, compare or solve before revealing the answer. Match the prompt to the ability being learned.
4. **Give useful feedback:** say what is sound, identify the most important error or missing step, explain why it matters, and offer one concrete next move.
5. **Retry or transfer:** when useful, invite a correction or a similar new task. Reduce hints as the learner gains control; ask them to interpret the result and name assumptions or limits.

Teach foundations before difficult retrieval. Once the learner can handle the basics, mix related examples when comparison helps them choose the right concept or method. Plan a later retrieval or practice as a spaced return when useful; adapt timing and challenge from the learner's evidence rather than prescribing a universal schedule.

For a static HTML lesson, put the question before its feedback and use the existing disclosure pattern when it supports a genuine attempt. Make feedback explain the answer, not merely reveal it. Do not imply that the page observed, scored or adapted to the learner. If the learner answers in a later chat, respond to that actual attempt, then choose one suitable retry or next step and adjust the challenge.

## Choose evidence of learning

- State a small number of observable outcomes: what the learner should be able to explain, solve, build, decide, say, write, or perform.
- If prior knowledge is uncertain, use a short, low-stakes diagnostic and give useful feedback. Adjust the starting point only from evidence.
- Separate knowledge of ideas from the ability to use or perform them when both matter.
- Fit the scope to the request and source. A short source does not need extra sections or exercises to satisfy a quota.

## Teach and practice each major idea

1. **Explain:** build the idea in a sensible sequence, define needed terms, and connect it to the source evidence.
2. **Model:** for a procedure or performance, show a worked example or demonstration. Make the important choices visible and explain why they work.
3. **Practice:** give the learner a related task that requires them to retrieve or use what was just taught. Start with enough support to make a first attempt possible, then fade hints as skill develops.
4. **Retrieve:** ask a short question or task before showing its answer. Use a format that resembles the intended learning: explanation, problem solving, code tracing, conversation, comparison, or performance.
5. **Give feedback and retry:** identify what is correct, explain the error or missing step, and give one actionable next move. When useful, let the learner correct or repeat the attempt.
6. **Transfer and judge:** ask the learner to use the idea in a new but related case, interpret the result, and name relevant assumptions or limits.

Teach new foundations before asking for difficult retrieval. Once the basics are established, mix related examples when comparison will help the learner choose the right method. Plan later retrieval or practice as a spaced return; choose timing and difficulty from the learner's evidence rather than applying a fixed schedule.

## Match the task to the subject

Choose practice and feedback that resemble the ability being learned:

- **Facts and concepts:** recall from a prompt, explain an idea in the learner's own words, distinguish it from a nearby idea, and support the explanation with the source.
- **Math:** study a worked solution, solve a related problem, explain the steps, and check whether the answer is reasonable.
- **Computer science:** predict output, trace or modify code, run it when possible, and diagnose a bug. Report only results that were actually tested.
- **Psychology and other evidence-based subjects:** distinguish a theory or construct from the evidence and the interpretation; apply it to a new case without presenting an inference as a source claim.
- **Languages:** include listening, reading, speaking, and writing when the format allows. Retrieve useful words in both directions, use grammar in original sentences, and include pronunciation or communicative practice when relevant. A text-only lesson can give a speaking or listening task, but should not claim to have observed the learner do it.
- **Sport and music:** demonstrate a movement or passage, isolate a manageable part, give one or two useful cues, and build toward the whole performance. Give feedback only on what can actually be observed; a guide that cannot see a performance should tell the learner what to notice or ask them to describe it.
- **Children:** use age-appropriate tasks, short instruction chunks, concrete examples, and visible cues. Adjust support and breaks to the learner's age, attention, and evidence of progress.

## Select learning techniques, do not decorate with them

Weave useful techniques into the lesson without naming their books or authors unless the learner asks. Choose a few that directly support the finish line; do not impose a quota of quizzes, breaks, analogies or review dates.

- Use meaningful chunks and explicit links to manage complexity and build a connected mental model.
- Use generation and retrieval to expose what the learner can recall or explain without the answer in view. Rereading and recognition alone can create an inflated sense of mastery.
- Use spaced returns for durable learning, and interleave related question types only after their foundations are taught. Interleaving should help the learner distinguish and choose, not make the first explanation confusing.
- For dense material, a focused pass followed by a brief pause and a synthesis prompt can be useful. Do not prescribe a universal timer or claim that a break guarantees learning.
- For a specific performance, define a narrow target, make a criterion for improvement visible, and use feedback and retry. Do not label ordinary self-study “deliberate practice” when it lacks expert guidance and repeated assessment.

Use analogies, diagrams, mnemonics and other memory cues only when they clarify relationships or help recall. Follow a cue with uncued retrieval and meaningful use; remembering a label alone does not show that the learner can apply the idea.

## Use memory supports selectively

Use retrieval and spaced returns to strengthen recall. Connect new ideas to familiar examples and use diagrams or vivid imagery when they clarify relationships. Mnemonics or a memory palace can help with arbitrary names, vocabulary, ordered steps, or other material that is hard to organize. Follow the memory cue with uncued retrieval and meaningful use; a memorized list alone does not show that the learner can apply the idea.

## Keep continuity records only when useful

For a continuing course or when the learner wants later sessions to build on this one, keep concise files beside the course materials:

- `MISSION.md`: the learner's goal, practical context, current level (if known), constraints, and what success looks like.
- `RESOURCES.md`: source IDs, title/type/link, useful page/time/slide/file anchors, and a short note about each source's contribution. Record conflicts and inaccessible portions.
- `NOTES.md`: concise concept explanations, worked examples, and links back to their source anchors.
- `learning-record.md`: only demonstrated knowledge, skills practiced, misconceptions corrected, and questions still open. Date entries and link to the exercise or learner response that supports them.

Start with the available files and update them only when the lesson provides new evidence. Do not treat silence, a guessed answer, or an unattempted exercise as proof of mastery. Keep records short so they make the next session more tailored instead of becoming a transcript.
